# Documentation map

WarTable keeps each topic in one canonical document. Start with the path for
your role, then use the authority table when two pages seem to disagree.

## Start here

- **First run:** [`quickstart/README.md`](../quickstart/README.md) — Docker or
  Compose on a trusted LAN.
- **Connect an agent:** the MCP section in [`README.md`](../README.md), then
  [`agent-instructions.md`](agent-instructions.md).
- **Configure it:** [`configuration.md`](configuration.md) — flags, `.env`, and
  environment keys.
- **Run it in production:** [`deployment.md`](deployment.md) — the supported
  contract for images, data, backups, updates, and security.

copying it. Add new facts to the owning page, not to every page that mentions
the topic.

## Current release

Releases are identified by git tags of the form `vX.Y.Z` and published on
[GitHub Releases](https://github.com/Alex98235/WarTable/releases). To find the
newest tag in a checkout:

```bash
git tag --sort=-v:refname | head -n 1
```

At the time of writing the newest tag is `v1.0.1`. Use the tag and GitHub
Release as the source of truth; this page does not track version numbers for
you. Container images use the same `X.Y.Z` version as an immutable tag, with
`latest` reserved for first runs.
